# 아쿠아잡(AQUA JOB) 설계 — 프리다이빙 강사·센터 연결 플랫폼

작성일: 2026-10-21 · 상태: 사용자 검토 대기 (빌더 검토 반영, v0 센터·강사·관리자 화면 대조 완료)

> 표기: **[사용자]** = 사용자가 직접 정한 것 · **[Claude 판단]** = 대화 중 Claude가 정했고 사용자가 바꿀 수 있는 것

---

## 1. 왜 만드나

- 프리다이빙을 배우다 강사가 된 사람이 소속 없이 혼자 개인 강습을 시작하면서 강습료가 터무니없이 낮아지고 있다. 프리랜서 강사가 늘수록 저가 경쟁은 더 심해진다. **[사용자]**
- 아쿠아잡은 강사가 혼자 가격을 깎는 대신 **센터와 연결되는 창구**가 되어, 강사 단가가 무너지지 않게 하는 것이 목표다. **[사용자]**
- 예전에 v0로 만든 "수영 강사 매칭" 시안(https://v0-aqua-job-pwa.vercel.app)이 있지만 화면만 있고 데이터는 가짜다. 대상을 **프리다이빙**으로 바꾸고 워너다이브 앱 수준으로 촘촘하게 **새로 만든다**. v0 코드는 재사용하지 않고 화면 구성만 참고한다. **[Claude 판단 — 사용자에게 설명함]**
- 나중에 핀프렌즈(멀티센터 플랫폼)에 합쳐질 수 있다. **[사용자]**

### 성공의 모습
- 신규 강사가 개인 강습을 열기 전에 아쿠아잡에서 센터 일을 먼저 찾는다.
- 센터는 검증 서류가 붙은 강사를 빠르게 찾아 직접 연락한다.
- 무료 기간(2~3개월) 동안 센터·강사 회원이 모이고, 이후 유료 전환이 가능하다.

## 2. 핵심 원칙 — 중립 **[사용자]**

- 아쿠아잡(관리자)은 **연결만** 한다. 단가 조정, 분쟁 중재, 추천, "좋은 강사/센터" 판정, 평점·순위 매기기를 하지 않는다.
- "아쿠아잡이 보증한 사람"이라는 인상을 주면 안 된다. 신뢰는 사람과 사람이 직접 판단한다.
- 단, **서류가 진짜인지는 확인한다.** 화면에는 **사실만** 표시한다. 예: "AIDA 강사 자격증 · 2027.03까지 · 서류 확인됨"
  - 금지 문구 예: "검증된 강사", "아쿠아잡 보증", "추천 강사"
- 서류로 확인된 정보와 본인이 입력한 정보(기록, 교육생 수 등)는 화면에서 구분해 보여준다. **[Claude 판단]**

### 안티골 (기술적으로 돌아가도 실패인 것)
- 플랫폼이 평가·보증하는 것처럼 보이는 UI나 문구
- 만료된 서류가 유효한 것처럼 계속 보이는 것 (= 잘못된 보증)
- 센터가 공고 없이 강사 연락처만 수집할 수 있는 구조
- 앱 안 채팅을 붙여 대화를 플랫폼에 묶어두는 것 (연결 후엔 당사자끼리 직접)

## 3. 사용자와 역할

| 역할 | 하는 일 |
|------|---------|
| 강사 | 이력서 작성, 서류 제출, 공고 열람·지원, 제안 수락/거절 |
| 센터 | 센터 정보·서류 제출, 공고 등록, 지원자 선택, 강사 둘러보기·제안 |
| 관리자(사장님 본인) | 서류 확인/반려, 회원·공고 조회, 신고 처리. 그 외 개입 없음 |

한 계정이 여러 역할을 가질 수 있다. **[사용자: "핀프렌즈처럼 관리자 강사 센터 상단 탭으로"]**
- 일반 가입은 역할 하나(강사 또는 센터)로 한다. 가입 화면에서 여러 역할을 고르지는 않는다.
- 관리자(사장님 본인) 계정처럼 여러 역할이 필요한 계정은 관리자가 SQL로 역할을 더 준다(`profiles.roles`). 앱 화면에서는 역할을 바꿀 수 없다.
- 역할이 둘 이상인 계정은 화면 맨 위에 [관리자] [강사] [센터] 탭(가진 역할만)이 생기고, 누르면 그 역할 화면으로 바로 바뀐다. 마지막으로 고른 탭은 기기에 기억한다. 처음엔 관리자 역할이 있으면 관리자 화면부터 연다.
- 처음 강사 탭을 열면 강사 이력서 마법사부터, 센터 탭은 센터 홈(사업자등록증 안내 포함)부터 시작한다. 낼 수 있는 서류 종류는 가진 역할들의 서류를 합친 것이다.
- 관리자 전용 주소(`/admin`)로 들어오면 관리자 화면부터 연다.

## 4. 연결 방식 **[사용자]**

공고는 두 종류다.
1. **수업 단위 섭외**: 특정 날짜·시간·장소의 수업에 강사를 부른다. 예: "11/2(토) 풀 세션 보조강사 1명, 회당 12만원"
2. **소속 계약**: 센터 정규 소속 강사를 구한다. 예: "주 3회, 평일 저녁, 월 협의"
3. **투어 동행 강사 모집**: 센터가 운영하는 국내·해외 투어에 **같이 갈 강사**를 구한다. 손님 모집은 하지 않는다. 여행업 사업자가 확인된 센터만 올릴 수 있다(§7). 예: "12/5~12/9 보홀 투어 동행 강사 1명" **[사용자]**

### 4-1. 지원 흐름
1. 센터가 공고를 올린다.
2. 강사가 지원한다. 프로필 이력서가 자동으로 첨부되고, 한 줄 메시지는 선택 사항이다. **[Claude 판단]**
3. 센터는 지원자 이력서와 서류 확인 내역을 보고 **선택**한다.
4. 선택하는 순간 **그 센터에만 강사 연락처(휴대폰, 이메일)가 열린다.** 강사에게는 "OO센터가 선택했어요" 알림이 간다.
5. 이후는 센터가 직접 연락한다. **앱 안 채팅은 없다.** **[사용자]**
6. 공고가 마감되면 선택되지 않은 지원자에게 "마감됐어요"만 알린다. **[Claude 판단]**
7. 강사는 지원을 취소할 수 있다. 단, 선택되기 전까지만 가능하다. **[Claude 판단]**
- 알림은 3단계에서 붙인다. 2단계에서는 강사의 "지원 현황" 화면에 상태(선택됨·마감·미선택)를 표시하는 것으로 대신한다. **[Claude 판단]**

### 4-2. 제안 흐름 **[사용자: 제안 기능 원함]**
1. 센터가 **강사 둘러보기**에서 필터로 강사를 찾는다. 필터: 지역, 자격 단체·등급, 가능 요일, 활동 범위(풀·바다·해외투어), 서류 확인 여부
2. 센터는 **자기 공고 하나를 골라** 제안한다. 모집 중인 공고가 없으면 제안할 수 없다. **[Claude 판단]**
3. 강사가 **수락**하면 연락처가 열리고 알림이 간다. 이후는 지원 흐름의 4~5와 같다. **거절**하면 센터에는 "정중히 거절했어요"만 표시된다.
4. 같은 강사에게 같은 공고로는 제안을 한 번만 보낼 수 있다. **[Claude 판단]**
5. 강사는 "센터에 내 프로필 공개" 스위치로 둘러보기 노출을 끌 수 있다. 꺼도 지원은 할 수 있다. **[Claude 판단]**
6. 둘러보기와 이력서 화면에서 **연락처는 항상 숨긴다.** 연락처가 열리는 경로는 "선택"과 "제안 수락" 두 가지뿐이다.

## 5. 강사 이력서 **[사용자: 항목 / Claude: 구성]**

- **기본**: 실명, 성별, 나이대, 활동 지역(복수), 프로필 사진, 연락처(휴대폰·이메일, 숨김)
- **성향**: MBTI, 자기소개, 수업 스타일(태그 + 자유 입력)
- **프리다이빙 스펙**: 자격 단체(AIDA·PADI·SSI·Molchanovs·CMAS 등)와 등급, 강사 등급, 강사 경력 연수, 누적 교육 인원(본인 입력), 개인 기록 STA·DYN·CWT·FIM(본인 입력)
  - 훈련 메트릭 표시 순서는 워너다이브 규칙을 따른다: STA → DYN → CWT → FIM
- **이력**: 활동했던 센터, 투어 경험, 가능 언어, 기타 자격(라이프가드, 응급처치 등)
- **가능 조건**: 가능 요일과 시간대, 활동 범위(풀·바다·해외투어), 희망 단가(선택)

## 6. 센터 프로필 **[사용자: 항목]**

- 센터명, 대표자, 대표강사, 소속강사(수·명단), 월 교육생 수(본인 입력)
- 주로 교육하는 요일과 시간대, 주 교육 장소(풀 이름, 바다 포인트, 해외 투어지)
- 사업장 주소(있으면 지도 표시), 사진
- 공고 이력: 지금까지 올린 공고와 제시 단가를 강사가 볼 수 있다. **[Claude 판단]**

## 7. 서류 확인 **[사용자: 확인 필요 / Claude: 세부]**

| 대상 | 서류 | 유효기간 관리 |
|------|------|---------------|
| 강사 | 강사 자격증 사진(단체·등급·번호) | 있음 (단체 회원 갱신일) |
| 강사 | 강사 배상책임보험 증서(DAN 등) | 있음 |
| 강사 | 응급처치·CPR 자격 | 있음 |
| 강사 | 신분증 | 없음 |
| 센터 | 사업자등록증 | 없음 |
| 센터 | 대표자 신분 확인 | 없음 |
| 센터 | 대표강사 자격증(선택) | 있음 |

- 제출 → 관리자 **확인 / 반려(사유 필수)**. 관리자는 진위, 이름 일치, 유효기간만 본다.
- 확인 시 관리자가 유효기간을 입력한다. 만료일이 지나면 자동으로 "만료" 표시로 바뀐다. 만료 30일 전과 만료일에 갱신 알림을 보낸다. **[Claude 판단]**
- **서류 이미지 원본은 관리자와 본인만 볼 수 있다.** 센터·강사 상대방에게는 "무엇이 언제까지 확인됐는지"만 보인다. 신분증은 절대 노출하지 않는다. **[Claude 판단]**
- **남에게 보이는 사실 = 유효 서류(확인됨·유효기간 안 지남, 종류별 가장 최근 확인 건), 본인 화면 = 최신 제출 상태(확인 대기·반려 포함).** 새로 낸 서류가 대기·반려여도 이전 확인 건이 유효하면 꼬리표와 요건 충족은 그대로다. 반려·대기·만료는 남에게 보이지 않는다. **[Claude 판단]**
- 강사는 서류 확인 없이도 가입·지원할 수 있다. 확인된 항목에만 꼬리표가 붙는다. 미확인 강사를 둘러보기에서 빼는 등의 노출 조건은 무료 기간 데이터를 보고 정한다. **[Claude 판단]**
- **센터는 사업자등록증이 확인돼야 공고 등록과 제안을 할 수 있다.** 가입과 프로필 작성은 확인 전에도 할 수 있다. **[사용자]**
- **투어 동행 강사 모집 공고는 여행업 사업자 등록이 확인돼야 올릴 수 있다.** 국내 투어와 해외 투어 모두 해당한다. **[사용자]**
- 이런 자격 제약은 앞으로 조금씩 늘어날 예정이다. **[사용자]** 그래서 "공고 종류 → 필요한 확인 서류" 규칙을 코드 곳곳에 박아 넣지 않고 **설정표 한 곳**에서 관리한다. 서류 종류를 추가하거나 규칙을 바꿀 때 화면과 서버 검사가 함께 따라오게 한다. **[Claude 판단]**
- 따라서 공고 종류는 세 가지가 된다: 수업 단위 섭외, 소속 계약, **투어 동행 강사 모집**(여행업 필요). 투어 공고는 수업 단위 공고 구조를 바탕으로 투어 기간(시작일~종료일), 행선지(국내·해외), 경비 부담 방식(항공·숙박 제공 여부)을 더한다. **[Claude 판단]**

### 7-1. 관리자 조치 **[사용자]**

- 관리자는 신고를 처리하면서 **공고 숨김, 계정 정지, 퇴출(영구 이용 정지)** 까지 할 수 있다.
- 중립 원칙과의 관계: 조치는 **규칙 위반**(가짜 서류, 허위 공고, 연락처 수집 목적 공고, 불법 행위)에 대해서만 한다. "좋다·나쁘다" 같은 평가는 하지 않는다. 조치 사유는 정해진 위반 항목 중에서 고르고 기록을 남긴다. 당사자에게는 사유를 알린다. **[Claude 판단]**
- 퇴출된 계정은 로그인할 수 없다. 퇴출된 센터의 공고는 숨겨진다. 이미 열린 연락처는 상대방 기록에 남는다. **[Claude 판단]**

## 8. 수익 구조 **[사용자]**

- 강사: **월 구독** → 센터 공고 열람
- 센터: **공고 등록 시 건당 결제**
- 계약 중개 수수료는 없음
- **첫 2~3개월은 무료.** 결제는 나중에 붙인다.
- 구현: "공고 열람"과 "공고 등록"에 **결제 관문 자리를 미리 만들어 두고**, 무료 기간에는 관문을 전부 통과시킨다. 기능 스위치 하나로 켜고 끈다. 결제 연동(PG)은 이번 범위가 아니다. **[Claude 판단]**

### 8-1. 로그인 안 한 사람 · 구독 안 한 강사에게 보이는 것 — 발레매니아 구조 **[사용자: 발레매니아처럼]**

참고: https://www.balletmania.com (무용 강사 구인구직)

발레매니아는 공고 목록과 공고 요약을 누구에게나 보여준다. 목록에는 지역, 제목, 학원명, 마감일이 나온다. 요약에는 분야, 지역, 시간당 페이가 나온다. 반면 **담당자·연락처·이메일·주소·홈페이지는 "열람신청"으로 잠가 둔다.** 아쿠아잡도 같은 구조로 간다.

| 보는 사람 | 공고 목록 | 공고 요약(종류·지역·일정·단가·자격 조건) | 상세 설명·센터 상세 프로필 | 지원·제안 수락 |
|---|---|---|---|---|
| 로그인 안 함 | 보임 | 보임 | 잠김 → "가입하고 보기" | 불가 |

## 11-1. 세부 규칙 (빌더 검토 후 Claude가 정한 것) **[Claude 판단]**

- **공고 인원과 마감**: 공고에는 모집 인원이 있다. 선택 수와 수락된 제안 수의 합은 모집 인원을 넘을 수 없다. 인원이 다 차거나, 마감일 또는 수업일이 지나거나, 센터가 직접 닫으면 마감된다. 선택과 수락은 서버 함수에서 행 잠금(`FOR UPDATE`)으로 처리해 인원 초과를 막는다.
- **선택 되돌리기 없음**: 한 번 열린 연락처는 계속 열려 있다. 실수로 선택하는 것을 막기 위해 선택 전에 확인 창을 띄운다.
- **제안 남발 방지**: 제안은 모집 중인 자기 공고로만 보낼 수 있다. 공고 하나당 보낼 수 있는 제안 수는 모집 인원 × 5로 제한한다.
- **신분증·사업자등록증 보관**:
  - 신분증은 주민번호 뒷자리를 가리고 올리도록 안내한다.
  - 확인이 끝나면 원본 이미지를 삭제하고 "신분증 확인됨(날짜)" 기록만 남긴다.
  - 자격증·보험 서류는 유효기간 관리를 위해 보관한다. 반려됐거나 교체된 파일은 30일 뒤에 지운다.
  - 계정을 탈퇴하면 서류를 전부 지운다.
- **약관과 개인정보처리방침**: Claude가 초안을 쓰고, 운영자·사업자 정보는 사용자가 채운다.
- **소속강사·경력 센터**: 1차에는 글자로만 입력한다. 실제 계정과 연결하지 않는다.
- **로그인 전 공개 범위**: §8-1로 대체한다. 공고 목록과 요약은 공개하고, 강사 프로필은 로그인한 센터에게만 보인다.

## 12. 이번 범위가 아닌 것 (비목표)

- 앱 안 채팅
- 결제·구독 연동 (자리만 준비)
- 평점·리뷰·추천·순위
- 계약서 작성·전자서명, 정산
- 휴대폰 본인인증
- 핀프렌즈·워너다이브 앱과의 실제 통합

## 13. 빌더에게 맡기는 것

- DB 테이블 세부 구조, 상태값 이름, 폴더 구조
- 필터 UI 세부, 빈 화면 문구, 알림 문구
- 사진·서류 업로드 압축 방식, 저장소(Supabase Storage 비공개 버킷) 세부
- 화면 전환과 애니메이션
